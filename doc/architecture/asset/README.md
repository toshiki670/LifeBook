# Asset コンテキスト設計ドキュメント

## 概要

Asset コンテキストは、個人の所有物（資産）を管理するための境界づけられたコンテキストです。商品の購入・売却・廃棄といったライフサイクル全体を追跡し、移動平均法による原価計算を実現します。

### 主要な特徴

- **トランザクション履歴管理**: 購入・売却・廃棄のすべての履歴を永続保存
- **移動平均法**: 複数回購入した商品の原価を自動計算
- **階層構造カテゴリ**: 無制限の階層でカテゴリを整理可能
- **多対多カテゴリ**: 1つの商品を複数のカテゴリに分類可能
- **完全な履歴保存**: Asset と AssetTransaction は削除されない

---

## 設計方針サマリー

### モデル構成

- **Asset**: 資産の集約根（削除不可）
- **AssetTransaction**: 資産の増減履歴（削除不可）
- **Product**: 商品マスタ（ソフトデリート）
- **Category**: 階層構造カテゴリ（孤児昇格 + ハードデリート）
- **Manufacturer**: メーカーマスタ（ソフトデリート）
- **ProductCategory**: Product と Category の多対多中間テーブル

### 削除ポリシー

| エンティティ | 削除方式 | 条件 |
|------------|---------|------|
| Asset | 削除不可 | 履歴として永続保存 |
| AssetTransaction | 削除不可 | 履歴は永続保存 |
| Product | ソフトデリート | Asset紐付き時は削除拒否 |
| Category | 孤児昇格 + ハードデリート | Product紐付き時は削除拒否 |
| Manufacturer | ソフトデリート | Product紐付き時は削除拒否 |

### よくある質問

**Q: なぜ Asset は削除できないのか？**  
A: 過去の所有履歴を完全に保持するためです。所有数がゼロになっても記録は残り、いつでもトランザクション履歴を参照できます。

**Q: Category と Subcategory の違いは？**  
A: Subcategory は存在しません。Category が階層構造を持ち、親子関係で無制限の階層を実現します。

**Q: 移動平均法とは？**  
A: 購入の都度、平均取得単価を再計算する原価計算方法です。詳細は [business-rules.md](./business-rules.md) を参照してください。

**Q: カテゴリ削除時に子カテゴリはどうなる？**  
A: 子カテゴリは自動的に親カテゴリに昇格します（孤児昇格）。ただし Product に紐づいている場合は削除拒否されます。
