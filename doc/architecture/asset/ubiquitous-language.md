# Asset コンテキスト - ユビキタス言語

Asset コンテキストで使用されるドメイン用語の定義です。開発チーム全体で共通の言葉を使うことで、ドメイン知識を正確に共有します。

---

## 基本概念

### Asset（資産）

個人が所有する物品の管理単位。Product と 1 対 1 で紐付き、現在の所有数量と取得原価を保持する。所有履歴は完全に保存され、削除されることはない。

**関連用語**:
- **所有状況**: `current_quantity > 0` で判断
- **所有中**: 数量が 1 以上の状態
- **過去に所有**: 数量がゼロだが記録は残っている状態

**例**:
- 「MacBook Pro 2024」という Asset を作成
- 購入すると `current_quantity = 1`
- 売却すると `current_quantity = 0`（でも Asset は残る）

---

### AssetTransaction（資産トランザクション）

資産の増減を記録する履歴。購入・売却・廃棄・調整の 4 種類がある。一度記録されたら変更・削除されることはない。

**トランザクション種別**:
- **PURCHASE（購入）**: 資産を取得した
- **SALE（売却）**: 資産を売却した
- **DISPOSAL（廃棄）**: 資産を廃棄した
- **ADJUSTMENT（調整）**: 数量や原価の調整

**例**:
```
AssetTransaction {
  type: PURCHASE,
  transaction_date: 2024-01-10,
  quantity: 2,
  unit_price: 5000,
  note: "Amazon購入"
}
```

---

### Product（商品）

持ち物の種類を表すマスタデータ。メーカーやカテゴリと紐付き、商品の基本情報を保持する。

**関連用語**:
- **商品マスタ**: Product のこと
- **廃番商品**: `deleted_at` が設定された Product

**例**:
- 「MacBook Pro 14インチ M3」という商品
- メーカー: Apple
- カテゴリ: 家電 > PC・タブレット > ノートPC

---

## カテゴリ体系

### Category（カテゴリ）

商品を分類するための階層構造。親子関係により無制限の階層を持てる。

**階層用語**:
- **ルートカテゴリ**: `parent_id` が null のカテゴリ（最上位）
- **親カテゴリ**: 上位の階層
- **子カテゴリ**: 直接の下位階層
- **子孫カテゴリ**: すべての下位階層（子、孫、ひ孫...）
- **祖先カテゴリ**: すべての上位階層（親、祖父母...）
- **階層の深さ（depth）**: ルートから何階層目か（0 起点）

**例**:
```
家電 (depth: 0) ← ルートカテゴリ
└─ オーディオ機器 (depth: 1) ← 親: 家電
   └─ イヤホン (depth: 2) ← 親: オーディオ機器、祖先: 家電
      └─ ワイヤレスイヤホン (depth: 3)
```

---

### カテゴリ操作

#### 孤児昇格（Orphan Promotion）

カテゴリ削除時に子カテゴリを親に繋ぎ直す操作。

**例**:
```
Before: 家電 → オーディオ機器 → イヤホン
Delete: オーディオ機器を削除
After:  家電 → イヤホン （イヤホンが昇格）
```

---

#### 親子間挿入（Insert Between）

既存の親子の間に新しいカテゴリを挿入する操作。

**例**:
```
Before: 家電 → イヤホン
Insert: オーディオ機器を挿入
After:  家電 → オーディオ機器 → イヤホン
```

---

#### 循環参照（Circular Reference）

自分の子孫を親にしてしまうエラー状態（禁止）。

**例**:
```
家電 → オーディオ機器 → イヤホン

NG: 「家電」の親を「イヤホン」に設定
  → 家電 → オーディオ → イヤホン → 家電 → ... (無限ループ)
```

---

### ProductCategory（商品カテゴリ紐付け）

Product と Category の多対多関係を管理する中間テーブル。1 つの商品が複数のカテゴリに属することができる。

**例**:
```
商品「ワイヤレスイヤホン」が属するカテゴリ:
- オーディオ機器 > イヤホン
- ワイヤレス製品
- 運動用品
```

---

## マスタデータ

### Manufacturer（メーカー・製造元）

商品を製造する企業や組織。名称は一意である必要がある。

**関連用語**:
- **アクティブなメーカー**: `deleted_at` が null
- **削除済みメーカー**: `deleted_at` が設定されているが、既存商品との紐付きは維持

**例**:
- Apple
- Sony
- 不明（デフォルト）

---

### MeasurementUnit（単位）

商品の数量を表す単位。

**単位種別**:
- **PIECE（個）**: 個数で数える（例: イヤホン 2個）
- **BOX（箱）**: 箱単位（例: ティッシュ 3箱）
- **PACK（パック）**: パック単位（例: 電池 2パック）
- **WEIGHT（重量）**: kg、g などの重量（例: コーヒー豆 500g）
- **VOLUME（容量）**: L、ml などの体積（例: シャンプー 1L）

---

## 原価計算

### 移動平均法（Moving Average Method）

購入の都度、平均取得単価を再計算する原価計算方法。

**用語**:
- **平均取得単価**: `total_acquisition_cost ÷ current_quantity`
- **総取得原価（total_acquisition_cost）**: 現在所有している分の取得原価合計
- **その時点の平均取得単価（unit_cost_at_time）**: トランザクション発生時の平均単価（売却損益計算用）
- **売却損益**: 売却価格 - 平均取得単価

**例**:
```
購入1: 2個 @ 5,000円 → 平均: 5,000円/個
購入2: 3個 @ 4,000円 → 平均: 4,400円/個（全体で）
売却:  1個 @ 3,500円 → 損益: -900円
```

---

### 計算プロセス

1. **購入時**: 新しい数量と金額を加算し、平均単価を再計算
2. **売却時**: その時点の平均単価で原価を減算し、損益を記録
3. **廃棄時**: 売却と同様に原価を減算（売却価格はゼロ）

---

## 削除と保存

### ソフトデリート（Soft Delete / 論理削除）

データを物理的に削除せず、`deleted_at` に削除日時を記録する方式。

**適用対象**:
- Manufacturer
- Product

**用語**:
- **アクティブ**: `deleted_at` が null の状態
- **削除済み**: `deleted_at` が設定されている状態
- **復元**: `deleted_at` を null に戻す操作

**メリット**:
- 既存データとの整合性を維持
- 誤削除からの復元が可能
- 「いつ使わなくなったか」の履歴が残る

**例**:
```
Manufacturer {
  name: "Sony",
  deleted_at: 2024-11-01  ← この日に削除された
}

→ 既存のProductは「Sony」を参照できる
→ 新規Product作成時には選択肢に出ない
```

---

### ハードデリート（Hard Delete / 物理削除）

データベースから実際にレコードを削除する方式。

**適用対象**:
- Category（孤児昇格後）

**理由**: 階層構造の柔軟な整理のため

**例**:
```
家電 → オーディオ機器 → イヤホン

「オーディオ機器」をハードデリート
→ データベースから完全に消える
→ 「イヤホン」は「家電」に昇格
```

---

### 削除不可（Non-Deletable）

削除機能自体を提供しない方針。

**適用対象**:
- Asset（履歴として永続保存）
- AssetTransaction（履歴は変更・削除しない）

**理由**: 過去の所有履歴を完全に保持するため

**例**:
```
Asset {
  name: "MacBook Pro 2020",
  current_quantity: 0  ← 売却済みだが削除しない
}

→ いつ買って、いつ売ったかの履歴が残る
→ 資産の推移を分析できる
```

---

### 削除拒否（Delete Rejection）

特定条件下で削除を拒否するビジネスルール。

**ルール**:
- Manufacturer: Product に紐づいている場合は削除不可
- Category: Product に紐づいている場合は削除不可
- Product: Asset に紐づいている場合は削除不可

**目的**: データの整合性を保護

**例**:
```
Category「イヤホン」を削除しようとする
→ 商品「AirPods Pro」が紐づいている
→ エラー: "Cannot delete: category has products"
→ 先に商品を別カテゴリに移動する必要がある
```

## ドメインロジック

### 集約（Aggregate）

DDD における一貫性の境界。

#### Asset 集約

```
Asset（集約根）
  └─ AssetTransaction（集約内）
```

**整合性ルール**: 
- トランザクション追加時に Asset のキャッシュを更新
- 両者の更新は同一トランザクション内で実行

**例**:
```rust
// OK: Asset と AssetTransaction を同時に更新
asset.add_purchase(2, 5000);
transaction.insert();

// NG: AssetTransaction だけ追加（整合性が壊れる）
transaction.insert();  // Asset が更新されない！
```

---

#### Product 集約

```
Product（集約根）
  ├─ Manufacturer（参照）
  └─ Category（多対多参照）
```

**整合性ルール**:
- Product 作成時に Manufacturer が存在することを確認
- Category との紐付けは ProductCategory 経由で管理

---

#### Category 集約

```
Category（集約根）
  └─ Category（自己参照による階層）
```

**整合性ルール**:
- 親変更時に循環参照をチェック
- 削除時に子カテゴリを昇格
- depth は常に親の depth + 1 を維持

---

### キャッシュ（Cache）

パフォーマンス最適化のため、計算結果を保存しておくこと。

**適用箇所**:
- `Asset.current_quantity`: トランザクションから計算可能だがキャッシュ
- `Asset.total_acquisition_cost`: トランザクションから計算可能だがキャッシュ
- `Category.depth`: 親を辿って計算可能だがキャッシュ

**更新タイミング**:
- Asset: トランザクション追加時に更新
- Category: 作成時、親変更時に更新

**なぜキャッシュするか**:
- 頻繁に参照される値を毎回計算するのは非効率
- 所有数や総原価はトランザクション履歴から集計できるが、O(1) で取得できる方が良い

---

## 原価計算用語

### 移動平均法（Moving Average Method）

購入の都度、平均取得単価を再計算する原価計算方法。

**基本用語**:
- **平均取得単価**: `total_acquisition_cost ÷ current_quantity`
- **総取得原価（total_acquisition_cost）**: 現在所有している分の取得原価合計
- **その時点の平均取得単価（unit_cost_at_time）**: トランザクション発生時の平均単価（売却損益計算用）
- **売却損益**: 売却価格 - 平均取得単価

---

### 計算例の用語

**購入時の計算**:
```
新しい数量 = 既存数量 + 購入数量
新しい総取得原価 = 既存原価 + 購入金額
新しい平均取得単価 = 新しい総取得原価 ÷ 新しい数量
```

**売却時の計算**:
```
減らす原価 = 平均取得単価 × 売却数量
新しい数量 = 既存数量 - 売却数量
新しい総取得原価 = 既存原価 - 減らす原価
売却損益 = 売却価格 - 平均取得単価
```

**廃棄時の計算**:
```
損失額 = 平均取得単価 × 廃棄数量
（売却と同じだが、売却価格はゼロ）
```

## カテゴリ階層用語

### 階層関係

- **ルートカテゴリ**: `parent_id` が null のカテゴリ（最上位）
  - 例: 「家電」「衣類」「書籍」
  
- **親カテゴリ**: 上位の階層
  - 例: 「イヤホン」の親は「オーディオ機器」
  
- **子カテゴリ**: 直接の下位階層
  - 例: 「オーディオ機器」の子は「イヤホン」「スピーカー」
  
- **子孫カテゴリ**: すべての下位階層（子、孫、ひ孫...）
  - 例: 「家電」の子孫は「オーディオ機器」「イヤホン」「ワイヤレスイヤホン」...
  
- **祖先カテゴリ**: すべての上位階層（親、祖父母...）
  - 例: 「ワイヤレスイヤホン」の祖先は「イヤホン」「オーディオ機器」「家電」

- **階層の深さ（depth）**: ルートから何階層目か（0 起点）
  - ルート = 0、第1階層 = 1、第2階層 = 2...

---

### カテゴリ操作

#### 孤児昇格（Orphan Promotion）

カテゴリ削除時に子カテゴリを親カテゴリに繋ぎ直す操作。

**別名**: 子の昇格、親への繋ぎ直し

**例**:
```
削除前: 家電 → オーディオ機器 → イヤホン → ワイヤレスイヤホン
削除:   「オーディオ機器」を削除
操作:   「イヤホン」の parent を「家電」に変更
        「イヤホン」と子孫の depth を -1
削除後: 家電 → イヤホン → ワイヤレスイヤホン
```

---

#### 親子間挿入（Insert Between）

既存の親子関係の間に新しいカテゴリを挿入する操作。

**別名**: カテゴリの挿入、中間カテゴリの作成

**例**:
```
挿入前: 家電 → イヤホン
        家電 → スピーカー
操作:   「オーディオ機器」を作成し、イヤホンとスピーカーを配下に
挿入後: 家電 → オーディオ機器 → イヤホン
                            → スピーカー
```

---

#### 循環参照（Circular Reference）

自分の子孫を親にしてしまうエラー状態。

**別名**: ループ、無限ループ、親子逆転

**検出方法**: 親を辿っていって自分自身に戻ってくるかチェック

---

### ProductCategory（商品カテゴリ紐付け）

Product と Category の多対多関係を管理する中間テーブル。

**別名**: 商品分類、カテゴリ紐付け

**用途**:
- 1つの商品を複数のカテゴリに分類
- タグ的な使い方も可能

---

## 削除関連用語

### ソフトデリート（Soft Delete）

データを物理的に削除せず、`deleted_at` に削除日時を記録する方式。

**別名**: 論理削除、Logical Delete

**対義語**: ハードデリート（物理削除）

**適用対象**: Manufacturer, Product

---

### ハードデリート（Hard Delete）

データベースから実際にレコードを削除する方式。

**別名**: 物理削除、Physical Delete

**対義語**: ソフトデリート（論理削除）

**適用対象**: Category

---

### 削除不可（Non-Deletable）

削除機能自体を提供しない方針。

**別名**: 永続保存、Immutable History

**適用対象**: Asset, AssetTransaction

**理由**: 履歴を完全に保持するため

---

### 削除拒否（Delete Rejection）

特定条件下で削除を拒否するビジネスルール。

**別名**: 削除前チェック、依存関係チェック

**適用例**:
- Manufacturer に Product が紐づいている → 削除不可
- Category に Product が紐づいている → 削除不可
- Product に Asset が紐づいている → 削除不可

---

## 技術用語

### 集約根（Aggregate Root）

DDD における集約の入口エンティティ。

**Asset コンテキストの集約根**:
- Asset
- Product
- Category

---

### 値オブジェクト（Value Object）

不変で交換可能なドメイン概念。

**Asset コンテキストの値オブジェクト**:
- MeasurementUnit（列挙型）
- TransactionType（列挙型）

---

### リポジトリ（Repository）

永続化の抽象化レイヤー。

**役割**:
- ドメインモデル ↔ DBモデルの変換
- CRUD操作のカプセル化

---

### DTO（Data Transfer Object）

レイヤー間でデータを転送するためのオブジェクト。

**用途**:
- ドメインモデルを直接公開せず、必要な情報だけを転送
- GraphQL レスポンスの形成

## 業務用語と技術用語の対応

| 業務用語 | 技術用語 | 説明 |
|---------|---------|------|
| 持ち物 | Asset | 所有する物品 |
| 商品 | Product | 持ち物の種類 |
| 購入履歴 | AssetTransaction (PURCHASE) | 購入記録 |
| 売却記録 | AssetTransaction (SALE) | 売却記録 |
| 分類 | Category | 商品の分類 |
| メーカー | Manufacturer | 製造元 |
| 単位 | MeasurementUnit | 数量の単位 |
| 平均価格 | 平均取得単価 | 移動平均法で計算した原価 |
| 利益・損失 | 売却損益 | 売却価格 - 取得原価 |
